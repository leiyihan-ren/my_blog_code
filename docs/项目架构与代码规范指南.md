# 项目架构与代码规范指南

> **项目**：my-blog 个人博客（Cloudflare Pages + 单 Worker + KV）
> **适用对象**：后续所有维护者（包括未来的你）
> **配套文档**：`docs/重构执行报告.md`（本次瘦身的执行明细）、`docs/开发与避坑指南.md`（部署/排坑手册）

---

## 1. 目录结构与模块职责

```
my-blog/
├── *.html                   # 9 个页面：index/blog/post/album/timeline/
│                            #   guestbook/games/links/admin
├── common.js                # 框架层：boot 流程、导航高亮、SEO 动态归一
├── common.css               # 全站唯一样式来源（CSS 变量，禁止内联硬编码）
├── js/
│   ├── utils.js             # ★ 工具函数单一事实源（window.BlogUtils）
│   └── request.js           # ★ 网络请求唯一入口（window.BlogApi）
├── game-core.js             # 游戏框架：生命周期/计时器登记/输入适配
├── games/*.js               # 7 个游戏，纯逻辑 step() 与渲染 draw() 已分离
├── music-player.js          # 播放器：状态闭包 + sync*UI/render* 函数级分层
├── sw.js                    # Service Worker：预缓存清单（新 JS 必须登记）
├── _worker.js               # Cloudflare 单 Worker：路由/KV/GitHub 代理/安全头
├── manifest.json            # PWA 清单
├── tests/                   # Playwright 测试（node tests/run-all.mjs）
└── docs/                    # 项目文档
```

### 1.1 加载顺序（head 中同步加载，勿随意调换）

```
common.js → js/utils.js → js/request.js → 页面内联脚本
```

页面内联脚本顶部用**别名接入**公共模块，调用点代码零改动：

```js
const { escapeHtml, escapeAttr, formatRelativeDate, toast } = window.BlogUtils;
```

### 1.2 核心模块职责边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| `BlogUtils` | 纯函数：转义/格式化/存储封装/防抖节流/toast | 任何网络请求、任何 DOM 结构假设 |
| `BlogApi` | 所有 `/api/*` 与 GitHub raw 请求：超时、重试、错误归一化、Loading 回调 | 不直接操作业务 DOM（如灯箱），Loading 由调用方回调管理 |
| `common.js` | 框架启动、SEO 双轨制（静态 meta + 运行时归一） | 业务逻辑 |
| 页面内联脚本 | 本页业务编排：状态 → 调 BlogApi/BlogUtils → 渲染 | 不复刻工具函数、不私建请求通道 |
| `game-core.js` | 游戏通用生命周期与输入适配 | 具体游戏规则（在 games/*.js） |
| `music-player.js` | 播放器全部状态与 UI | 不复刻工具函数（已收敛至 BlogUtils） |
| `_worker.js` | 服务端：路由表、KV 数据仓、GitHub 代理、CSP 安全头 | 前端逻辑 |

## 2. 新增功能的标准姿势

### 2.1 新页面

1. 从结构最接近的现有页面复制骨架；
2. `<head>` 中按 §1.1 顺序引三个脚本；
3. 内联脚本顶部写别名，**禁止**再定义 escapeHtml/toast 等；
4. 数据请求一律走 `BlogApi.get/post(...)`，带 `onLoading` 管理按钮态；
5. 新静态资源（JS/CSS）登记进 `sw.js` PRECACHE_URLS；
6. SEO：静态 meta 照现有格式写生产域名（喂爬虫），运行时归一交给 common.js。

### 2.2 新工具函数

判断归属：纯逻辑无副作用 → `js/utils.js`；涉及网络 → `js/request.js`。
加函数必须带 JSDoc，导出挂到 `window.BlogUtils` / `window.BlogApi` 上。

### 2.3 新游戏

1. 在 `games/` 新建文件，继承 game-core 的 BaseGame；
2. 规则逻辑写在 `step()`，画面写在 `draw()`，两者不互相调用；
3. 输入只走框架适配层，不直接绑 keydown；
4. 在 `games.html` 注册入口。

### 2.4 新 API 接口

1. `_worker.js` 路由表注册，响应统一过 `buildHeaders`（CSP 等安全头全站一致）；
2. 前端调用走 `BlogApi`，错误信息已归一化为 `{status, message, data}`；
3. 涉及 GitHub 数据仓（照片/音乐）走 `/api/github/*` 代理，前端不直连第三方 CDN。

### 2.5 提交与回归纪律

- 每次改动跑 `node tests/run-all.mjs`（467 断言基线，全绿才算完）；
- 重构类改动遵循「每次抽离立刻局部测试」，恶性耦合只记录不强拆；
- commit message 用 `refactor/fix/feat/docs` 前缀，说清为什么。

## 3. 部署约定（Cloudflare Pages）

- 站点根目录即仓库根目录：**构建命令留空，构建输出目录填 `/`**；
- `package.json` 仅承载测试依赖（playwright），已通过 `config.playwright_skip_browser_download=1`
  保证部署平台执行 `npm ci` 时**不下载测试浏览器**（浏览器只应由 CI 的
  `npx playwright install chromium` 显式安装）；
- `_worker.js` 位于根目录，输出目录为 `/` 时 Pages 高级模式自动接管；
- Git 推送触发 Actions（全链路测试）+ Pages 自动部署；如需手动兜底，
  可用 Direct Upload 拖拽整站 zip。

## 4. 红线清单（违反即制造新屎山）

1. ❌ 在任何页面/文件里重新定义 `escapeHtml`、`escapeAttr`、`toast`、`formatDate`——用别名；
2. ❌ 页面里直接 `fetch('/api/...')`——必须走 `BlogApi`（否则丢超时/重试/错误归一化）；
3. ❌ 在 `request.js` 里写业务 DOM 操作——Loading 态用 `onLoading` / `onSuccess` 回调交还调用方；
4. ❌ 内联 `style="color:#xxx"` 硬编码——进 common.css 用 CSS 变量；
5. ❌ 蛇形/拼音变量名——统一驼峰，英文命名；
6. ❌ 新增 JS 文件不登记 `sw.js`——离线用户立刻缺资源；
7. ❌ 未经回归全绿就合并——测试是这套架构的唯一护栏。
