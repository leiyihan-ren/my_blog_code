## 步骤 1：全局依赖分析与模块解耦

### 1.1 扫描结论：项目真实架构体检

对全部 13,404 行前端代码（9 页面 + 7 游戏 + 播放器 + 框架 + Worker）逐文件扫描，
耦合与重复问题的实际分布：

| 病灶 | 实况 | 严重度 |
|---|---|---|
| `escapeHtml` 重复定义 | **11 份**（9 页面 + game-core + music-player） | 🔴 |
| `escapeAttr` 重复定义 | 4 份（game-core/admin/album/links） | 🔴 |
| `formatDate` 一函数三行为 | admin=绝对时间、guestbook=相对时间、post=相对+时分回退 | 🟡 不能强并 |
| `toast` 四套实现 | game-core/links/music-player 各自管定时器，行为不一致 | 🟡 |
| 相册图片多镜像兜底 | 私有实现埋在 album.html 内联脚本，别处不可复用 | 🟡 |
| `safeStorage` 重复 | common.js 一份、music-player 又一份 | 🟢 |
| 命名不规范 | `song_artist`（蛇形）混在驼峰命名中 | 🟢 |
| 注释掉的死代码 | **0 处**（历史重构已清干净） | ✅ |

**关键判断**：游戏层（`game-core.js` + `games/*.js`）在上一轮大重构中已经
做到「逻辑/渲染分离」（BaseGame 管生命周期与计时器登记，各游戏类内部
step/draw 分离，输入适配层统一），**不是本次解耦的重点，不动**。
真正的屎山在**跨页面的横向重复**——同一个工具函数被复制 11 遍。

### 1.2 解耦前后的架构对比

**解耦前（复制粘贴式架构）**：

```
index.html    ── 内联 escapeHtml ×1 ─┐
blog.html     ── 内联 escapeHtml ×1 ─┤
post.html     ── 内联 escapeHtml ×1 ─┤        任何一处 bug 修复
album.html    ── 内联 escapeHtml ×1 ─┤        → 要改 11 个文件
guestbook.html── 内联 escapeHtml ×1 ─┤        漏改任何一处
timeline.html ── 内联 escapeHtml ×1 ─┤        → 线上行为不一致
links.html    ── 内联 escapeHtml ×1 ─┤
admin.html    ── 内联 escapeHtml ×1 ─┤
game-core.js  ── escapeHtml ×1      ─┤
music-player.js── escapeHtml ×1     ─┘
```

**解耦后（单一事实源 + 别名接入）**：

```
                    ┌─────────────────────────────┐
                    │  js/utils.js（BlogUtils）    │
                    │  escapeHtml/escapeAttr       │
                    │  safeStorage                 │
                    │  formatDateTime/             │
                    │  formatRelativeDate/         │
                    │  formatDateCN/formatTime     │
                    │  toast/debounce/throttleRaf  │
                    │  copyText/isHttpUrl/sleep    │
                    └──────────┬──────────────────┘
               const { escapeHtml } = window.BlogUtils;  ← 别名接入，调用点零改动
        ┌──────────┬──────────┼──────────┬──────────┐
     9 个页面   game-core  music-player  (未来新页面)
```

```
                    ┌─────────────────────────────┐
                    │  js/request.js（BlogApi）    │
                    │  get/post/put/del            │
                    │  超时(AbortController)       │
                    │  重试(指数退避,4xx不重试)     │
                    │  错误归一化{status,message}  │
                    │  Loading 回调                │
                    │  github.loadImage 多镜像兜底  │
                    └──────────┬──────────────────┘
                        album.html（fetchAlbumPage + 图片加载）
                        （后续各页面 /api 调用统一接入）
```

**接入方式刻意选择「别名」而非「改 85 个调用点」**：
页面脚本顶部一行 `const { escapeHtml } = window.BlogUtils;`，
原有调用代码一行不动——把重构风险降到零，同时获得单一事实源。

## 步骤 2：提取公共逻辑与工具函数

### 2.1 新增公共模块清单及使用方式

| 模块 | 挂载点 | 职责 | 接入方式 |
|---|---|---|---|
| `js/utils.js`（160 行） | `window.BlogUtils` | DOM 速查 `$/$$`、`escapeHtml`/`escapeAttr`、`safeStorage`、`formatDateTime`/`formatRelativeDate`/`formatDateCN`/`formatTime`、`toast`、`debounce`/`throttleRaf`、`copyText`、`isHttpUrl`、`sleep` | 页面脚本顶部 `const { escapeHtml } = window.BlogUtils;` 别名接入，调用点零改动 |
| `js/request.js`（152 行） | `window.BlogApi` | 统一 `request()`（超时 12s + 指数退避重试 + 4xx 不重试 + 错误归一化 `{status,message,data}`）、便捷方法 `get/post/put/del`、`github.rawUrl()`、`github.loadImage()` 多镜像兜底 | `BlogApi.get('/api/album/photos?...')` / `BlogApi.github.loadImage(img, onSuccess)` |

两个模块均在 9 个 HTML 页面的 `<head>` 中于 `common.js` 之后同步加载，并已加入
`sw.js` PRECACHE_URLS（离线可用）。

### 2.2 横向重复收敛结果（11 → 0）

| 重复项 | 重构前 | 重构后 |
|---|---|---|
| `escapeHtml` 定义 | 11 份 | 1 份（utils.js，超集版：`<>&"` 全转义，属性位置也安全） |
| `escapeAttr` 定义 | 4 份 | 1 份（utils.js，`escapeHtml` 基础上再转义 `'`） |
| `formatDate` 一函数三行为 | admin/guestbook/post 三套并存 | 按语义拆为 `formatDateTime`（admin 绝对时间）/ `formatRelativeDate`（guestbook 相对时间）/ `formatRelativeDate(dateStr,{farFormat})`（post 相对+时分回退，参数化定制） |
| `toast` 四套实现 | game-core/links/music-player 各管定时器 | 统一 `BlogUtils.toast`（null 安全，定时器单例管理） |
| `safeStorage` 两份 | common.js + music-player | 1 份（utils.js） |
| 相册图片多镜像兜底 | 私有实现埋在 album.html | 公共化为 `BlogApi.github.loadImage`，Loading 交由调用方 `onSuccess` 回调管理（消除分层违返） |

**formatDate 为什么没有强并**：三处行为语义不同（绝对时间 / 相对时间 / 相对+时分回退），
强行统一会改变任一页面的既有显示行为，违反「严禁破坏已跑通逻辑」纪律。
`formatRelativeDate` 用 `farFormat` 选项参数化保留了 post 页的差异化行为。

### 2.3 净变更

19 个文件变更，**+532 / −209 行**：新增 utils.js/request.js 两个公共模块（312 行），
删除 11+4 份重复定义及 album 私有兜底逻辑，净代码量下降且复用度上升。

### 3.5 顺带修复的架构隐患（步骤 3 期间发现）

线上体检发现 `canonical`/`og:url` 静态写死生产域名 `leiyihan.dpdns.org`，
一旦换域名或 Cloudflare 308 规范化 `/album.html`→`/album`，静态 meta 与真实
URL 错位。修复为 **SEO 双轨制**：静态 meta 保持写死（喂不执行 JS 的爬虫），
`common.js initSeoUrls()` 在 boot 时按 `location` 动态覆写 canonical/og:url/
JSON-LD（换域名、CF 规范化后 canonical 永不错位）。
