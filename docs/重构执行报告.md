## 步骤 1：全局依赖分析与模块解耦

### 1.1 扫描结论：项目真实架构体检

对全部 13,404 行前端代码（9 页面 + 7 游戏 + 播放器 + 框架 + Worker）逐文件扫描，
耦合与重复问题的实际分布：

| 病灶 | 实况 | 严重度 |
|---|---|---|
| `escapeHtml` 重复定义 | **11 份**（9 页面 + game-core + music-player） | 🔴 |
| `escapeAttr` 重复定义 | 4 份（game-core/admin/album/links） | 🔴 |
| `formatDate` 一函数三行为 | admin=绝对时间、guestbook=相对时间、post=相对+时分回退 | 🟡 不能强并 |
| `toast` 四套实现 | game-core/links/music-player 各自管定时器，行为不一致 | 🟡 |
| 相册图片多镜像兜底 | 私有实现埋在 album.html 内联脚本，别处不可复用 | 🟡 |
| `safeStorage` 重复 | common.js 一份、music-player 又一份 | 🟢 |
| 命名不规范 | `song_artist`（蛇形）混在驼峰命名中 | 🟢 |
| 注释掉的死代码 | **0 处**（历史重构已清干净） | ✅ |

**关键判断**：游戏层（`game-core.js` + `games/*.js`）在上一轮大重构中已经
做到「逻辑/渲染分离」（BaseGame 管生命周期与计时器登记，各游戏类内部
step/draw 分离，输入适配层统一），**不是本次解耦的重点，不动**。
真正的屎山在**跨页面的横向重复**——同一个工具函数被复制 11 遍。

### 1.2 解耦前后的架构对比

**解耦前（复制粘贴式架构）**：

```
index.html    ── 内联 escapeHtml ×1 ─┐
blog.html     ── 内联 escapeHtml ×1 ─┤
post.html     ── 内联 escapeHtml ×1 ─┤        任何一处 bug 修复
album.html    ── 内联 escapeHtml ×1 ─┤        → 要改 11 个文件
guestbook.html── 内联 escapeHtml ×1 ─┤        漏改任何一处
timeline.html ── 内联 escapeHtml ×1 ─┤        → 线上行为不一致
links.html    ── 内联 escapeHtml ×1 ─┤
admin.html    ── 内联 escapeHtml ×1 ─┤
game-core.js  ── escapeHtml ×1      ─┤
music-player.js── escapeHtml ×1     ─┘
```

**解耦后（单一事实源 + 别名接入）**：

```
                    ┌─────────────────────────────┐
                    │  js/utils.js（BlogUtils）    │
                    │  escapeHtml/escapeAttr       │
                    │  safeStorage                 │
                    │  formatDateTime/             │
                    │  formatRelativeDate/         │
                    │  formatDateCN/formatTime     │
                    │  toast/debounce/throttleRaf  │
                    │  copyText/isHttpUrl/sleep    │
                    └──────────┬──────────────────┘
               const { escapeHtml } = window.BlogUtils;  ← 别名接入，调用点零改动
        ┌──────────┬──────────┼──────────┬──────────┐
     9 个页面   game-core  music-player  (未来新页面)
```

```
                    ┌─────────────────────────────┐
                    │  js/request.js（BlogApi）    │
                    │  get/post/put/del            │
                    │  超时(AbortController)       │
                    │  重试(指数退避,4xx不重试)     │
                    │  错误归一化{status,message}  │
                    │  Loading 回调                │
                    │  github.loadImage 多镜像兜底  │
                    └──────────┬──────────────────┘
                        album.html（fetchAlbumPage + 图片加载）
                        （后续各页面 /api 调用统一接入）
```

**接入方式刻意选择「别名」而非「改 85 个调用点」**：
页面脚本顶部一行 `const { escapeHtml } = window.BlogUtils;`，
原有调用代码一行不动——把重构风险降到零，同时获得单一事实源。
