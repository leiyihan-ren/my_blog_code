# 开发与避坑指南

> 本指南收录本项目在全量压测、UI 打磨与无障碍整改中**真实踩过并已修复**的坑，以及后续开发必须遵守的纪律。
> 每条标注：现象 → 根因 → 解法 → 涉及文件。新增代码前通读一遍可避开绝大多数夜间 debug。

---

## 一、Shell 与环境坑

### 1.1 pkill 会自杀（模式串匹配自身命令行）

```bash
# ❌ 危险：这条命令会 SIGTERM 自己（整行命令行含 "http.server 8601" 模式串）
pkill -f "http.server 8601"; python3 -m http.server 8601 …
```

**解法**：用端口杀进程，且与服务器启动**分成两条命令**：

```bash
fuser -k 8601/tcp 2>/dev/null   # 只杀占用端口的进程
# （下一条命令再启动服务器）
```

### 1.2 Playwright 截图的两种坐标参照系

- `page.screenshot({ clip })` 的 clip 用**文档坐标**（滚动后原点在文档顶部）
- `loc.boundingBox()` 返回**视口坐标**（相对当前视口）

两者混用 → 滚动后错位，截到错误区域（曾把 footer 的紫色回顶按钮当成文字背景，误报对比度 1.30:1）。

**解法**：元素级截图一律用 `loc.screenshot({ path })`，原生处理滚动，无需手算坐标。

### 1.3 视觉回归基线必须从对应 commit 重新导出

`git archive <commit> | tar -x -C /tmp/vis-orig` 得到的基线是**那个 commit 的快照**。拿过期基线与新版对比，会把中间已修复的差异重复报出来（曾一次误报 124 条 `#999` 修复差异）。

**纪律**：每个阶段用**上一阶段的 HEAD** 做基线重新导出，再跑回归。

## 二、CSS / UI 坑

### 2.1 同一个色值兼任背景与文字时，对比度不可兼得

`--primary: #4f46e5` 配白字（按钮背景）达 6.3:1，但直接用作暗色模式下的文字色只有 2.49~3.16:1。

**解法**：拆**文字专用令牌** `--primary-text`（亮 `#4f46e5` / 暗 `#818cf8`），73 处文字用途切换；背景/边框用途继续用 `--primary`（UI 组件 3:1 即可）。**新颜色上线前先问：它会被同时用作背景和文字吗？**

### 2.2 DOM 读取的对比度是区间，不是真值

渐变背景上 `getComputedStyle` 只能拿到 `background-image` 字符串，算不出真实对比度。

**解法**：像素级真值法——元素级截图 + PIL 取**非文字像素的众数颜色**（量化 8 级）作为文字背后主导背景。注意多区域元素（如 footer 内含回顶按钮）：取极端亮度值会把按钮像素误判为背景，众数法不受此影响。

### 2.3 标签语义变更（h2→h1、div→button）会静默丢失样式

`<h2>标题</h2>` 改成 `<h1>` 后，`.not-found h2 { color: … }` 选择器失配，标题回落到继承色——**JS 无报错、页面不崩，只是颜色弱化了**。

**解法**：标签更名必须全局搜索对应选择器同步修改；跑归一化视觉回归（路径剥离标签名）验证。同类：`div.tab → button.tab` 需补 `font-family:inherit; background:none; border:none` 继承外观。

### 2.4 弹性布局默认 `min-width:auto` 会撑破容器

flex 子项里的长文本/URL 不收缩，把整个头部挤出屏幕。

**解法**：`.header-inner > * { min-width: 0 }` + 全局 `overflow-wrap: break-word`。

### 2.5 改 `</div>` 的批量替换是重灾区

一次 tab 按钮化改造中，防护正则把 11+ 处无关的 `</div>` 误改为 `</button>`，HTML 结构静默损坏（浏览器容错渲染，肉眼难察）。

**解法与纪律**：
1. 批量结构替换**必须配对开闭标签一起替换**，拒绝"只换开标签"
2. 改完立即跑 HTML 栈平衡校验（Python `html.parser` 跳过 script 内容，比正则计数可靠）
3. 多行变更不要用 difflib 逐行对齐还原（replace 块不等长会 0 匹配），按内容模式定位修复

## 三、JavaScript 坑

### 3.1 原始计时器不在框架管辖内 = 幽灵回调

扫雷把 `setInterval` 注册在 `reset()`，重开叠加多个秒表；贪吃蛇重开双循环速度翻倍；Dpad 长按连发在切游戏后仍向废弃实例派发方向（"幽灵操作"）。

**解法**：`BaseGame` 统一登记 `after/every/raf/rafLoop/on`，pause/start/gameOver 自动 `clearTimers`，destroy 自动 `offAll`。**新增游戏一律用登记版，禁止裸调原生 API。**

### 3.2 innerHTML 全量重建会吞掉 CSS 动画

扫雷每次翻牌全量 `innerHTML` 重建棋盘，`.flip`/`.flag`/`.boom` 动画永远播不出来（新 DOM 直接就是终态）。

**解法**：一次性建格 + 原地更新 `class`/`textContent`，让过渡有"从旧态到新态"的过程。

### 3.3 切歌竞态：慢网络连点两首会互相覆盖

快速连点两首歌，第一个 `audio.src` 的 `onerror`/封面加载回调后置到达，把第二首的 UI 覆盖成第一首的状态。

**解法**：`loadToken` 自增令牌，每个异步回调先查 `myToken !== loadToken` 就 return。同理用于封面 `img.onerror`。

### 3.4 连续加载失败会无限自动切歌

某首歌 URL 失效 → `error` 事件 → 自动切下一首 → 也失效 → 无限循环，用户永远被偷走播放控制权。

**解法**：`consecutiveErrors` 计数，达阈值停止自动切换；`playing` 事件归零。手动切歌取消未触发的 `pendingSwitch`。

### 3.5 事件监听互相覆盖：`onkeydown =` 是独占的

游戏早期劫持 `document.onkeydown = …`，会把播放器的键盘快捷键整条覆盖掉（后者赋不上值）。

**解法**：一律 `addEventListener`；播放器再叠一级让位链——游戏运行中（`GameCore.isGameRunning()`）、灯箱打开（`.lightbox.active`）、焦点在表单/按钮、组合键，四级全不命中才响应。

### 3.6 点击后的焦点残留：空格/回车会二次触发

鼠标点过「开始」后按钮保持 focus，用户按空格翻页/暂停时又触发一次按钮。

**解法**：舞台按钮统一 `blur(fn)` 包装——执行后 `e.currentTarget.blur()`。

### 3.7 对象存不了纯数字键的有序表

`{ "2048": …, snake: … }` 枚举时 `"2048"` 被排到最前，游戏卡片与排行榜顺序错乱。

**解法**：注册表用 `Map`。

### 3.8 escapeHtml 不转义引号，属性上下文会注入

`<div data-id="${escapeHtml(x)}">`，若 `x` 含 `"` 可闭合属性注入 `onmouseover` 等。

**解法**：`escapeAttr`（escapeHtml + 替换引号）；**规则：文本用 escapeHtml，属性一律 escapeAttr。**

### 3.9 隐私模式下 localStorage 抛错会中断整页脚本

`localStorage.setItem` 在隐私模式/存储禁用时抛 `SecurityError`，一条未捕获异常会让后面全部初始化代码不执行。

**解法**：全项目统一 `safeStorage` 包裹（admin/music-player/game-core 三处各自定义，刻意不共享以保组件独立）。

## 四、后端 / Worker 坑

### 4.1 KV 键名散落字符串 = 备份清理双漏洞

键名硬编码在业务代码里时，`deletePrefix` 清理与备份导出容易漏。

**解法**：全部收进 `KEYS` 常量（`site/posts/messages/comments_<id>/gh_*/…`），新存储先加常量。

### 4.2 公开写端点不限流 = 被刷穿

留言/评论/点赞/提交分数四条公开写路径，任何一条漏了 IP 级限流（冷却 + 每小时上限）都会被脚本刷爆 KV 写入配额。

**解法**：新增公开写端点必须在 `handlers` 里补齐限流三件套（cooldown 键 + hour 键 + 锁定键），并在 ROUTES 表标注 `needBody`。

### 4.3 路径参数可能带畸形百分号编码

`/api/post/%ZZ` 直接 `decodeURIComponent` 会抛异常导致 500。

**解法**：`matchRoute` 里 try/catch，解码失败置 `null` 交给下游校验返回 400。

### 4.4 双内容源的「删除复活」问题

后台删掉一条 GitHub 同步来的文章，仓库不变 → 下次合并它又出现。

**解法**：`deleted_ids` 墓碑键（`{ posts:[], music:[], timeline:[] }`），删除仓库来源条目时记 id，合并层据此隐藏。导入备份会连带墓碑，删本地内容前先想清楚墓碑语义。

### 4.5 备份导入必须校验形状

用户导入一个 `{}` 或数组，全量覆盖会清空站点。

**解法**：`importBackup` 校验 `payload.data` 存在且为对象；前端同样预检并 confirm 二次警告。

### 4.6 认证模型：token = 密码本身

后台用 `Authorization: Bearer <管理密码>`，sessionStorage 生命周期（关标签页即失效）。不要把它升级成"长效 token"——那等于把密码落盘。旧版本曾写 localStorage，现有代码做了一次性迁移清理（`tokenStorage.remove`）。

## 五、测试方法论（复现全部结论）

```bash
# 静态服务器（页面无后端时跑 UI 测试）
python3 -m http.server 8899            # 工作版
git archive <基线commit> | tar -x -C /tmp/vis-orig
python3 -m http.server 8601 --directory /tmp/vis-orig   # 基线版

node /tmp/smoke-ui.mjs        # HTML 配对 / FOUC / 对比度 / 375px 溢出 / JS 错误
node /tmp/smoke-routes.mjs    # 页面互通 / SEO meta / 关键元素 / 主题切换
node /tmp/smoke-games.mjs     # 2048/扫雷/记忆翻牌核心逻辑
node /tmp/stress-games.mjs    # 连点 / gameOver spam / 提交 spam / 暂停恢复 spam
node /tmp/stress-music.mjs    # 拖动 spam / 键盘 spam / 切后台 / 灯箱抢占
node /tmp/a11y-audit.mjs      # 地标/标题/alt/图标按钮/emoji/表单标签/可交互 div
node /tmp/kbd-runtime.mjs     # 灯箱 + 4 模态：焦点移入/陷阱/Esc/归还（21 断言）
node /tmp/visreg-norm.mjs     # 归一化视觉回归（路径剥标签名，只报真实样式差异）
```

**测试编写教训**：
- 检测 `<main>` 用 `/<main[\s>]/g`，不要 `/<main>/g`（漏带 class 的合法写法）
- 键盘测试派发 `KeyboardEvent` 后查 `defaultPrevented` 验证陷阱行为
- 需要 API 数据的页面（album photos）在测试里先 `page.evaluate` 注入数据再触发交互

## 六、提交前检查单

```bash
# 1. 结构：HTML 栈平衡（9 页 0 错误）
# 2. 语法：内联 JS 提取后 node --check
# 3. 视觉：visreg-norm.mjs vs 上一 commit（真实差异 0）
# 4. 冒烟：smoke-ui + smoke-routes + smoke-games 全绿
# 5. 压力：stress-games + stress-music 全绿
# 6. a11y：a11y-audit.mjs 无新增告警；动过模态/灯箱必跑 kbd-runtime.mjs
# 7. 令牌：新颜色/圆角先进 :root，禁止散落硬编码
```

**金句三条**：
1. 计时器和监听器不进框架管辖，就等于给未来的自己埋幽灵 bug。
2. 批量改结构，开闭标签必须一起改，改完立刻跑栈平衡校验。
3. 任何"背景兼文字"的颜色，上线前先跑一遍双模式像素级对比度。
