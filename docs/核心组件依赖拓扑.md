## 2. 前端层依赖

### 2.1 页面清单与脚本装载

| 页面 | 职责 | 装载的脚本（顺序） | 独占内联逻辑 |
|------|------|--------------------|--------------|
| index.html | 首页：资料卡 + 热门文章 + 最新动态 | components/music-player.js(defer) | 统计/热门渲染、主题 FOUC 同步 |
| blog.html | 文章列表 + 关键词搜索高亮 | components/music-player.js(defer) | 列表渲染、搜索过滤 |
| post.html | 文章详情 + 评论 + 点赞/阅读 | components/music-player.js(defer) | 评论 CRUD、点赞、上下篇 |
| album.html | 相册网格 + 灯箱 + 懒加载 | components/music-player.js(defer) | 灯箱（2.4b 对话框语义）、多镜像兜底 |
| timeline.html | 时间线流 | components/music-player.js(defer) | 列表渲染 |
| guestbook.html | 留言板 | components/music-player.js(defer) | 留言提交（60s 冷却） |
| links.html | 友链卡片 + 申请面板 | components/music-player.js(defer) | 复制站点信息 |
| games.html | 游戏大厅 + 排行榜 | components/game-core.js → components/games/snake.js → breakout.js → g2048.js → memory.js → mines.js → components/music-player.js(defer) | 舞台 DOM、主题、导航 |
| admin.html | 管理后台（9 个 Tab） | 无外部脚本（全部内联） | 登录、CRUD、备份、GitHub 状态面板 |

**关键约束**：
- `components/game-core.js` 必须先于全部 `components/games/*.js` 装载（子游戏在装载时即调 `GameCore.register` 自注册）
- `components/music-player.js` 用 `defer` 且自带 IIFE 隔离，与页面内联脚本无耦合（唯一耦合点：`window.showToast` 可选复用、`GameCore.isGameRunning()` 查询）

### 2.2 组件间横向依赖

```
components/music-player.js ──查询──▶ GameCore.isGameRunning()   （游戏进行中让位键盘快捷键）
components/music-player.js ──查询──▶ .lightbox.active           （灯箱打开时让位方向键）
components/music-player.js ──复用──▶ window.showToast（存在则用，否则自降级）
components/games/*.js    ──依赖──▶ window.GameCore（BaseGame/register/fitCanvas/toast）
components/game-core.js  ──操作──▶ games.html 舞台 DOM（#board/#overlay/#stage-score/…）
admin.html    ──依赖──▶ /api/*（无其他前端依赖，完全独立）
```

> 设计原则：**组件零相互 import**。播放器与游戏只通过 `window.GameCore` 全局单例和 DOM 状态类名松耦合感知彼此，任何一方缺失都不影响另一方运行。

## 3. 后端层依赖（_worker.js）

### 3.1 模块结构（单文件 2648 行，按注释分区）

```
_worker.js
├── 1. 工具（safeKvKey / escape / json 响应 / ETag）
├── 2. CONFIG（限流阈值 / GitHub 参数 / 长度上限）
├── 3. 安全（安全响应头 / XSS 净化 / 频率限制）
├── 4. 认证（Bearer token = 管理密码本身，sessionStorage 生命周期）
├── 5. 内容合并（双来源：KV 后台内容 + GitHub 仓库内容 + 删除墓碑）
├── 6. KEYS（KV 键名统一管理，禁止散落字符串）
├── 7. Store（KV 读写 + 前缀删除 + defer 批处理）
├── 8. GitHub 同步（多源拉取 + KV 缓存 TTL + 状态面板数据）
├── 9. handlers（39 个端点的业务实现）
├── 10. 限流（点赞 IP 去重 / 留言冷却 / 评论冷却）
├── 11. 备份（导出全量 / 导入校验）
└── 12. ROUTES（表驱动：[方法, 路径模式, handler, 需管理员, 需请求体]）
```

## 4. 存储层（KV）

### 4.1 数据键（`KEYS` 常量，禁止散落）

| 键 | 内容 | 写入方 |
|----|------|--------|
| `site` | 站点配置（标题/简介/GitHub 参数/自动模式） | 后台 |
| `posts` / `timeline` / `music` / `links` | 内容数组 | 后台 |
| `messages` | 留言数组 | 公开（留言板）+ 后台删除 |
| `comments_<postId>` | 每篇文章一个键 | 公开（评论）+ 后台删除 |
| `likes` / `views` | `{ [postId]: number }` 聚合索引 | 公开（点赞/阅读） |
| `gameScores` | `{ [gameId]: Score[] }` | 公开（提交）+ 后台清空 |
| `deleted_ids` | 双来源「删除墓碑」`{ posts:[], music:[], timeline:[] }` | 后台删除 GitHub 来源条目时 |
| `gh_status` | GitHub 最近拉取状态（后台排查面板） | 系统 |
| `gh_<type>_<repo>_<branch>_<path>_<cdn\|raw>` | GitHub 内容缓存（TTL） | 系统 |
| `like_*` / `likeip_*` / `likerate_*` | 点赞 IP 去重与限流 | 系统 |
| `msg_rate_*` / `msg_hour_*` / `comment_rate_*` / `comment_hour_*` | 留言/评论限流 | 系统 |
| `lock_<ip>` | 安全锁 | 系统 |

### 4.2 双内容源合并模型

```
读取文章列表 =
    KV 后台文章（后台发布/编辑，优先）
  + GitHub 仓库文章（仓库新增，自动补充）
  − deleted_ids 墓碑（后台删过的仓库条目，隐藏）
```

GitHub 拉取链路：`raw.githubusercontent.com` ⇄ `cdn.jsdelivr.net` 双源互备 → 写入 `gh_*` 缓存键（TTL）→ 合并层。后台「刷新缓存」= 删除 `gh_` 前缀全部键。

## 5. 外部依赖

| 依赖 | 用途 | 失败时的行为 |
|------|------|--------------|
| GitHub raw / jsDelivr | 文章/音乐/相册图片的仓库内容源 | 双源互备 → KV 过期缓存兜底（`usingStale` 标记）→ 后台只显示 KV 内容 |
| `localStorage` / `sessionStorage` | 主题、播放器音量/模式/收起态、游戏昵称与最佳、管理 token | `safeStorage` 包裹 try/catch，隐私模式降级不抛错 |
| `navigator.mediaSession` | 锁屏/耳机按键媒体控制 | 特性检测，不支持则静默跳过 |
| Cloudflare KV | 全部持久化数据 | Worker 运行时保障，无客户端兜底 |

## 6. 关键不变量（改动前必读）

1. **装载顺序**：`components/game-core.js` 必须第一个装载；子游戏文件装载即自注册，缺 core 会静默失败（控制台报错）。
2. **admin.html 零外部脚本**：后台所有逻辑内联，改后台不得引入外部依赖（单文件可离线审计）。
3. **KV 键只进 `KEYS`**：新增存储必须加常量，散落字符串键会导致备份/清理遗漏。
4. **公开写入必须限流**：留言/评论/点赞/提交分数四条公开写路径都带 IP 级限流，新增公开写端点必须补齐。
5. **播放器/游戏键盘让位链**：游戏运行中 → 播放器让位；灯箱打开 → 播放器让位。新增全屏组件时需接入同一条链。
6. **`escapeHtml` 与 `escapeAttr` 分用**：属性上下文（`"` `'`）必须用 `escapeAttr`，`escapeHtml` 不转义引号。
